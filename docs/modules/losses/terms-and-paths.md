# Loss terms and their paths in `openftgs.losses`

How `openftgs.losses` meets its §2.1 row for E7, E8 and E9: the three terms of the rendering loss L_render, the perceptual networks of D-89, the 4D regularization L_reg and the total loss L. The input layout, the API details §2.1 leaves open and the SSIM paths are the owner's answers recorded in `docs/clean-room/questions.md` (Q-41, Q-42); the networks' input checks are Q-261's and, for the Caffe trunks, Q-263's and, for the DINO networks, Q-265's, and λ_perc = None is Q-249's. The signature of `total_loss` (D-77) and U-11's reading of the stop-gradient (D-78) entered the spec in revision 549c, and the perceptual networks (D-89) in revision 549o.

## Input layout

Every image term takes `pred` and `gt` in §1.4's layout, height × width × 3, with any leading dimensions. A single training image and `RenderOutput.image`, which has one leading camera dimension, both fit. The leading dimensions flatten into a batch, and every term averages over the batch, the pixels and the channels (Q-41). One private helper checks the two images and turns them into the batch-first, channel-second view that the convolutions need. On a contiguous channels-last tensor that view is already in channels-last memory format, so nothing is copied; only the fused-ssim path copies, because fused-ssim reads contiguous batch-first tensors. No term clamps the render: E2 clamps colors only at zero, so Î can exceed one, and only the metrics clamp (E7, E16).

## The two SSIM paths

`ssim` returns SSIM itself; the loss term is one minus it. Its constants scale with the data range, as the glossary's SSIM_k does, so evaluation can ask for SSIM₂ with the same function (D-67).

There are two paths behind the one function (§2.4 "Where the time goes", D-52):

- **fused-ssim**, the optional `[fast]` speed-up (Q-2). It hardcodes E7's window, σ, constants and data range, runs on CUDA in float32, and differentiates only its first image. `ssim` uses it only when all of that holds and the target image doesn't require a gradient (Q-42). The module imports it once, lazily, and treats an import failure as "not installed", without a warning. The installed package reports only its version, not the commit the tests ran with (Q-2), so the commit pin is a documented install instruction, not something the code checks.
- **The PyTorch fallback**, used everywhere else: on the CPU, in float64, with other constants, or when the target needs a gradient. It filters the two images, their squares and their product with the separable Gaussian window in one grouped convolution, and forms SSIM from population moments (D-8). It is written from the SSIM definition, not from either library, and its numerator and denominator are built symmetrically, so an image compared with itself gives exactly SSIM's maximum (U-9).

The two paths agree in value. "same" means zero padding in both, and fused-ssim's "valid" is a crop of its zero-padded map, which equals unpadded filtering. Their gradients can differ only where fused-ssim clamps a pixel's SSIM to its mathematical range, a numerical guard the fallback doesn't need (Q-42). On the GPU the fallback's convolution runs in TF32 during training, PyTorch's default, which is D-52's one approximate default; tests that compare the paths clear the flag.

B-4 (#228, Calibration data) measured what fused-ssim gains: its forward and the prediction's backward take 0.41 ms at 1352×1014 and 0.66 ms at 1920×1080, against 8.5 and 13.2 ms for the PyTorch fallback in TF32, about 95 % less, so it stays in use whenever it imports and Q-42 needs no second look.

## The perceptual networks

`PerceptualLoss(net)` builds the perceptual network `LossConfig.perc_net` names, one of D-89's eight, ꟻLIP by default (D-9). A name outside D-89's table is a ValueError before anything is built, LPIPS's "vgg" and "alex" among them, which `LossConfig` already refuses, naming revision 549o (#375; Q-247 for the checkpoints that carry them). What every network shares is D-89's common contract:

- `forward(pred, gt)` takes two images in Q-41's layout, [..., H, W, 3] of one shape, dtype and device, checked on their shapes alone, and returns the mean over the batch as a 0-d tensor.
- The reference is detached, D-89's "reference without a gradient": it gets none even when it asks for one, and autograd records nothing on its branch, the separate no-grad pass §2.4 asks for.
- The network is frozen and in evaluation mode. `.train()` leaves it there, also when a parent module calls it.

**ꟻLIP** (`flip`) is the vendored LDR-ꟻLIP loss of `openftgs._vendor.flip` (`docs/modules/losses/vendored-flip.md`), on the batch-first views of the two images at 67.0 pixels per degree. The value is passed as a Python float, the key of the vendored copy's filter cache, so a training loss and #387's metric at the same value share the filters. 67.0 and the published default, 67.02, give filters of the same size but not the same values. The loss clamps both images to [0, 1] itself, so a render above 1 gets no gradient there, while L1 and SSIM still see it. Its constants are float32, so it refuses images of another dtype with a ValueError rather than casting them (Q-261). On identical images it gives about 3.2·10⁻⁷, its stabilizer, not 0.

**HaarPSI** (`haarpsi`) is 1 − HaarPSI with D-89's settings, piq's defaults: 3 scales, subsampled, c = 30, α = 4.2, and a data range of 1. The render is clamped to [0, 1] first. It is adapted from piq 0.8.0's `haarpsi` (Apache-2.0, NOTICE; source log 446 to 448), not imported: piq is not a dependency, and it requires torchvision. The code carries piq's attribution and lists what changed, and on random images it agrees with piq bitwise in float32 and float64, on the CPU and on CUDA. The changes:

- piq's `assert`s give way to Q-41's checks and piq's 16-pixel minimum side, which three scales need. Its check that both images lie in [0, 1] goes: it reads them back to the host, a synchronization §2.4 rule 3 forbids, and D-89's clamp of the render covers it. The reference, E7's I in [0, 1], is used as given (Q-261).
- HaarPSI computes in its images' dtype, as piq does, but `PerceptualLoss.forward` takes float32 and float64 images only, ahead of the adapted code, and refuses any other with a ValueError naming both, without casting (Q-261). piq takes any floating dtype: in float16 the squares of the 4- and 8-pixel Haar coefficients, on the 0–255 scale, pass float16's 65504 and the value is NaN, with no error; in bfloat16 it is an approximation, 1.5 % off float64's on a noisy pair, that B-4 never measured.
- The YIQ matrix and the Haar filters are built once per device and dtype and kept, outside inference mode, as the vendored ꟻLIP keeps its constants. piq copied the matrix to the device at every call.
- The pairs of Haar channels are strided slices rather than piq's tuple indices, which copy an index tensor to the device.

So after one call on a device, a forward and backward pass make no synchronization. Two quirks come with piq's construction. HaarPSI of two flat images is infinite, because their weights are all zero. And in float32, 1 − HaarPSI(I, I) is a few 10⁻⁶ rather than 0, from rounding the logit of float32's sigmoid(4.2): up to 3.2·10⁻⁵ of its value under σ = 16/255 noise, above U-9's 10⁻⁵. In float64 it is below 10⁻¹⁴, so U-9 checks HaarPSI's identity case in float64 (owner, Q-262).

**The Caffe trunks** (`vgg16_oxford`, `alexnet_bvlc`) are lpips's uncalibrated distance, every channel weighted equally, on Oxford's VGG16 and BVLC's AlexNet, built as #374 tested them (D-89). They are trunk networks, the first two of the six. The private module `openftgs._caffe_trunks` builds them from the tensors `trunk_tensors` returns (next section); like `openftgs._weights`, it imports nothing from openftgs, and `PerceptualLoss` passes it the weights. The construction is adapted from #374's prototype (source log 449):

- **The input** is Caffe's: the RGB render, unclamped, flipped to BGR, times 255, minus the release's mean pixel. Oxford's is (103.939, 116.779, 123.68). BVLC's is the per-channel mean of its mean image, which #374 subtracted to eight decimals and D-89's table rounds to three; the code keeps the eight (Q-264).
- **VGG16's layers** are five blocks of 3×3 convolutions with padding 1, each followed by its ReLU, tapped after relu1_2, relu2_2, relu3_3, relu4_3 and relu5_3, with 2×2 max pooling of stride 2 between the blocks.
- **AlexNet's layers** are conv1 (11×11, stride 4), conv2 (5×5, padding 2) and conv3 to conv5 (3×3, padding 1), with conv2, conv4 and conv5 in two groups, tapped after relu1 to relu5. After the first two taps come Caffe's local response normalization (5 channels, α = 10⁻⁴, β = 0.75, k = 1) and 3×3 max pooling of stride 2.
- **The pooling** is Caffe's ceiling mode: a side n gives ⌈(n − k)/s⌉ + 1, a partial window at the bottom and right counting, as PyTorch's `ceil_mode=True` computes it. Nothing after the last tap is computed.
- **The distance** divides each tap's feature vectors by their norm plus 10⁻¹⁰, lpips's ε, sums the squared differences over channels, averages them over space and sums the five taps; the loss is the mean over the batch. The reference's features are computed without a gradient. On identical images both trunks give exactly 0.
- **The inputs refused** (Q-263): a trunk computes in its weights' dtype, float32 as converted, so images of another dtype are a ValueError, not cast, as for ꟻLIP. AlexNet refuses a height or width below 23 pixels, the smallest its layers take; VGG16 takes any size. Both checks read only shapes and dtypes, so they don't synchronize.
- **The weights** are buffers left out of the `state_dict`: `.to()` moves and converts them, and nothing that saves the module carries them (§2.3: never redistributed). Building a trunk hashes its converted file, 59 MB for VGG16 and 9 MB for AlexNet (Q-258).
- **The layout:** `PerceptualLoss` takes the images as its caller lays them out; a render's batch-first view is channels-last in memory, and goes in with no copy. B-4 measures each network with contiguous NCHW inputs and with this view, with cuDNN autotuning off and on (#389; `docs/modules/cli/benchmarks.md`). Since #394 the trainer's private subclass copies both images to NCHW for these two trunks, under every precision for AlexNet and under IEEE float32 and autotuned TF32 for VGG16, where B-4 measured that faster, and autotunes VGG16 under TF32 and AlexNet under TF32 and bfloat16 (Q-273; `docs/modules/train/trainer.md`); every other caller passes the render's view. Under bfloat16 autocast, the way the trainer's opt-in bfloat16 runs every trunk network (Q-172, Q-250; `docs/modules/train/trainer.md`), the images still enter as float32, so the dtype check holds.

Oxford's weights are licensed under CC BY 4.0, so NOTICE attributes them to Simonyan and Zisserman's report, "Very Deep Convolutional Networks for Large-Scale Image Recognition" (arXiv:1409.1556), as §2.3's note asks. BVLC's AlexNet is released for unrestricted use.

**The DINO networks** (`dinov2_s14`, `dinov2_b14`, `dino_s16`, `dino_b16`) are trunk networks built as #374 tested them (D-89), adapted from its prototype with attribution (source log 452), on the DINOv2 layers of the vendored RoMa (D-65, `docs/modules/init/vendored-roma.md`):

- **The trunk.** The vendored `vit_small` or `vit_base`, 12 blocks: patch 14 with DINOv2's layer scale, or patch 16 without it for DINO v1, whose weights load into the same layers. Each is built for the side its publisher's position embeddings were made for, 518 or 224 pixels, so that the state dict `openftgs._weights` returns loads as saved: DINOv2's whole, DINO's whole but for DINOv2's mask token, which the network never uses without masks. Any other mismatch is a RuntimeError, since the file has already passed its hash. The vendored model interpolates its position embeddings to the image with its own code. Once the state dict has loaded and passed that check, each of the vendored model's parameters becomes a buffer of the same name and value, left out of the `state_dict`, as the Caffe trunks hold theirs (Q-263, Q-265): `.to()` moves and converts them, the vendored layers read them as attributes, so their files stay unchanged (D-65), and nothing that saves the module carries them. Nothing saves a perceptual network's state anyway. The trainer's state, and so a checkpoint, holds the model's stored tensors, their Adam state and the gradient statistics, never the loss's (§2.2; `test_a_checkpoint_holds_no_perceptual_network`), and neither the evaluator nor the harness's adapter saves its network, so the weights stay where §2.3 puts them, downloaded at first use and never redistributed.
- **The input.** Each image at half resolution, bilinear and antialiased, a side halved to `round(side / 2)`, rounded half to even as the prototype rounds it (Q-265); centre-cropped to a multiple of the patch; standardized with ImageNet's mean and standard deviation. These two are buffers, so `.to(device)` moves them and no call copies them to the device.
- **The distance.** The patch tokens after blocks 3, 6, 9 and 12, before the model's final norm and without the class token, each unit-normalized over its channels with lpips's ε = 10⁻¹⁰ (source log 435); their squared differences summed over channels, averaged over tokens and summed over the four blocks; the mean over the batch. The reference's tokens are computed under `torch.no_grad()`. On identical images the value is exactly 0 (U-9).
- **The inputs refused** (Q-265), after Q-41's checks and before any work: images of a dtype other than the weights', float32 as built, with a ValueError naming both rather than a cast, as for the Caffe trunks (Q-263); converted by `.to(torch.float64)`, a network takes float64 images, and its value is held to the construction test's oracle; and a side that halves to less than one patch, which would leave no token. The smallest height and width are 27 pixels for DINOv2 and 31 for DINO.
- **`[init]`.** The vendored package's `__init__` modules import torchvision, einops and loguru, which only the `[init]` extra installs. `openftgs.losses` imports the layers only when a DINO network is built, so the module and the other four networks stay in the core. Without the extra, building a DINO network raises an ImportError naming it ("needs the [init] extra (pip install 'openftgs[init]')") before anything is downloaded, which the CLI turns into exit code 2 (Q-248, Q-142).

The CPU tests build the DINO networks on stand-in tensors with the publishers' keys and shapes, so their construction is checked without a download: the trunk's input against D-89's, written out, and the value against the distance computed from each block's output, as built in float32 and converted to float64. The `weights` tests (Q-7) load the publishers' files, check that they load whole and that the stand-ins have their shapes, and run U-9.

## The trunk weights

The six trunk networks of D-89 get their pretrained tensors from `openftgs._weights`, a private top-level module that imports nothing from openftgs, so `openftgs.losses` may import it under §2.1's band order, and nothing of the `[init]` extra (Q-248). Two functions are its entry points. `trunk_tensors(name)` returns a trunk's tensors as float32 on the CPU, fetched at first use; building the network from them is the network's own code (D-89's construction column). `trunk_files(name)` returns the files in torch.hub's cache any one of which builds the trunk without a download, in the order `trunk_tensors` looks for them, and reads, makes and downloads nothing: `ftgs bench losses`, which never downloads, checks with it that every trunk is cached before it runs (#389; Q-253, Q-270). Beside them, `TRUNKS` names the six, `DOWNLOADS` and `Download` hold each publisher's pinned file, and `fetch` is the checked download `trunk_tensors` makes, which the `weights` tests call to fill the cache.

- **Where the files come from.** Each trunk is pinned to its publisher's file: the URL, the byte count and the SHA-256 that source-log rows 419, 421, 424 and 440 record (`DOWNLOADS`). The file is downloaded at first use into torch.hub's checkpoint folder under its publisher's name, the folder RoMa's weights use (§2.3's note on weights: downloaded at run time, never redistributed).
- **The check.** Oxford's and BVLC's hosts serve plain HTTP, so the hash is the integrity check (§2.3). A file is checked, byte count first and then SHA-256, before every use, not only after its download. A download goes to a temporary file and enters the cache only once it passes, so a failed, truncated or altered download leaves nothing behind. A cached file that fails is refused and left in place for the user to delete, never overwritten (Q-258).
- **The Caffe trunks.** `vgg16_oxford` and `alexnet_bvlc` are published as Caffe files. A reader of protobuf's wire format, with Caffe's field numbers (source-log row 422) and neither protobuf nor caffe.proto, takes the convolutions D-89's distance reads, adapted from #374's prototype (source log 438). They are cached once as safetensors beside the source, under Caffe's layer names, and the input channels stay in Caffe's BGR order, which the network's input map expects (D-89). The converted file is checked at every load against the publishers' layer shapes and a digest of its data pinned in the code (Q-258); the fully connected layers are never read.
- **The DINO trunks.** The four ViT checkpoints are checked, then loaded with `torch.load(..., weights_only=True)` as the state dicts their publishers saved. The vendored DINOv2 layers they load into need `[init]`; reading the tensors needs only torch (Q-248).
- **Errors.** A failed download, every refused file and a conversion that can't be written (no permission, a full disk) raise `OSError`, the environment error the CLI turns into exit code 2 (Q-142); the message names the URL or the cached file. safetensors reports a failed write through its own class, so the conversion's is wrapped, as `openftgs.io`'s writers do (Q-158), and leaves nothing in the cache (Q-258, #407).

The CPU tests check the cache and its refusals with small stand-in files and a publisher's host on the loopback address. The `weights` tests (Q-7) download the six real files and check their hashes, the converted tensors' layer shapes and the DINO state dicts (`tests/test_weights.py`).

## The 4D regularization

`reg4d_loss` is the mean of the per-row terms of E8 that `openftgs.motion.reg4d_terms` computes (Q-12), at the training image's time in normalized time, never a raw timestamp (§1.4, Q-41); `total_loss` passes its `t` on unchanged. The stop-gradient on the temporal opacity therefore lives in one place, the motion module's private helper, which the temporal slice shares. The mean runs over all N rows, visible or not (D-11), and an empty model gives zero rather than NaN (Q-41). The function reads the model's parameters when it is called, so a test can substitute them with `torch.func.functional_call` (U-11). Because the stop-gradient leaves L_reg's value moving with μt and ŝ while its gradient through them is zero, U-11's gradient check evaluates L_reg with only the opacity logits substituted (D-78). The terms are recomputed eagerly, one elementwise pass over N, because `render` doesn't hand the trainer its slice. B-1 measured that pass's forward (`loss.reg`) on kitchen at 0.04 to 0.13 ms, 0.04 to 0.11 % of an iteration from 0.5M to 3M rows (#226; its backward is interleaved with the other losses' and can't be timed apart), far under the 5 % at which PRD #220 asks for a change, so it stays.

## The total loss

`total_loss` composes E7 and E9 (D-37) from `LossConfig`:

- The perceptual network is passed in as the keyword `perceptual`, a `PerceptualLoss` built once by the trainer (D-77).
- The returned dict holds detached zero-dimensional tensors on the images' device, so computing the loss never synchronizes with the host (§2.4 rule 3, D-77). The trainer reads them at its logging period.
- A term whose λ is zero is not computed and has no key for the whole run, which saves the perceptual pass in λ_perc = 0 ablations (Q-41).
- After `reg_until`, which names the last iteration with L_reg (D-10), L_reg leaves the total but is still reported under its key, computed without a gradient. The keys therefore stay fixed for a run, and the loss trace D-10 names shows L_reg after a cutoff (Q-41, owner's answer).
- The iteration index is counted as D-41 counts it.
- λ_perc = None is the calibrated weight of `LossConfig.perc_net`, D-89's λ column: 0.415 for ꟻLIP, 0.0617 for HaarPSI, and the trunk networks' from 0.00164 to 0.00484. A private resolver in this module looks it up, so §2.1 gains nothing and no other module imports a private name. The trainer, the harness adapter and `ftgs bench` build the network when λ_perc is None or positive, and `config.json` keeps `null` as written (Q-249). None is the default, with ꟻLIP, so the default loss is ꟻLIP at 0.415 (§2.1 `LossConfig`, §1.5 table C).
- `total_loss` raises when the resolved weight is positive and no network is passed (D-77, Q-249).
- A perceptual network built for another `perc_net` than `LossConfig.perc_net` is rejected, whatever λ_perc (D-9, Q-41). `PerceptualLoss` keeps the name it was built for.
